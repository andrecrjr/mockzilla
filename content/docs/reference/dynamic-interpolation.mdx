# Dynamic Data Syntax

Dynamic data keeps ordinary endpoint mocks useful without creating a custom response for every variation.

## Request values

Use request values to reflect the request in a response:

| Value | Syntax |
|---|---|
| Query parameter | `{{$.query.page}}` |
| Request body | `{{$.body.email}}` |
| Path parameter | `{{$.params.id}}` |
| Header | `{{$.headers.x-request-id}}` |

```json
{
  "id": "{{$.params.id}}",
  "email": "{{$.body.email}}",
  "page": "{{$.query.page}}"
}
```

## Generated values

Use Faker and time helpers for realistic mock data:

| Helper | Example |
|---|---|
| Faker | `{{faker.person.fullName}}` |
| UUID | `{{faker.string.uuid}}` |
| Current time | `{{now}}` |
| Date format | `{{dateFormat now "yyyy-MM-dd"}}` |
| Date arithmetic | `{{dateAdd "now" 7 "days"}}` |

## Formatting and logic

| Helper | Example |
|---|---|
| Fallback | `{{default $.query.locale "en-US"}}` |
| Conditional | `{{#if $.query.debug}}...{{/if}}` |
| Comparison | `{{#if (eq $.query.plan "pro")}}...{{/if}}` |
| Math | `{{math $.query.page "+" 1}}` |
| String format | `{{slugify $.body.title}}` |
| Currency | `{{currency 1234.56 "USD"}}` |

## Collections

Use `filter`, `sort`, `slice`, and `json` to shape a response collection before returning it:

```handlebars
{
  "items": [
    {{#each (slice (sort products "price" "asc") 0 5)}}
    { "id": "{{this.id}}", "name": "{{this.name}}" }{{#unless @last}},{{/unless}}
    {{/each}}
  ]
}
```

## Journeys

Journey Actions use Handlebars for declared field writes, headers, and response body. Keep stateful behavior in declared Journey lifecycles, Fields, and clear Actions—rather than using templates as a substitute for a readable API flow.

See [Journeys](/docs/concepts/journeys) and [JSON Schema & Faker](/docs/reference/json-schema).
