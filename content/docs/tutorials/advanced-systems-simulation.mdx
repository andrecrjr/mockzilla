# Tutorial: Delivery in a Customer Journey

> **Planned product:** This tutorial documents the Journey contract, ahead of runtime support.

Delivery is a separate Lifecycle track, so it can follow checkout without replacing its state:

```text
checkout: pending → paid → shipped
delivery: not_started → tracking → delivered
```

```json
[
  {
    "name": "Start delivery",
    "method": "POST",
    "path": "/orders/:id/delivery",
    "requires": { "checkout": "shipped", "delivery": "not_started" },
    "transitions": { "delivery": "tracking" },
    "setFields": { "trackingCode": "{{faker.string.alphanumeric}}" },
    "statusCode": 202,
    "body": { "id": "{{params.id}}", "trackingCode": "{{fields.trackingCode}}", "status": "{{state.delivery}}" }
  },
  {
    "name": "Track delivery",
    "method": "GET",
    "path": "/orders/:id/delivery",
    "requires": { "delivery": "tracking" },
    "transitions": { "delivery": "delivered" },
    "statusCode": 200,
    "body": { "id": "{{params.id}}", "status": "{{state.delivery}}" }
  }
]
```

This tests loading and delivered UI states while carrying one tracking code—without a hidden polling counter or mini-database. Reset restores every lifecycle track and Field to its initial value.

Read [Journeys](/docs/concepts/journeys) for the full model and [Creating a Journey](/docs/guides/creating-journeys) for the authoring contract.
