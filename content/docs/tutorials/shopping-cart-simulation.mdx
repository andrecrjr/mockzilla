# Tutorial: Checkout in a Customer Journey

> **Planned product:** This is a Journey design example. It is not a supported runtime format yet.

Checkout is one track of a larger customer Journey:

```text
auth:     signed_out → authenticated
checkout: browsing → pending → paid → shipped
```

Keep product listings, cart payloads, and independent endpoint data in ordinary mocks inside folders/subfolders. Use the Journey for the visible lifecycle change.

```json
[
  {
    "name": "Pay",
    "method": "POST",
    "path": "/orders/:id/pay",
    "requires": { "auth": "authenticated", "checkout": "pending" },
    "transitions": { "checkout": "paid" },
    "setFields": { "orderId": "{{params.id}}" },
    "statusCode": 200,
    "body": { "id": "{{fields.orderId}}", "status": "{{state.checkout}}" }
  },
  {
    "name": "Ship",
    "method": "POST",
    "path": "/orders/:id/ship",
    "requires": { "auth": "authenticated", "checkout": "paid" },
    "transitions": { "checkout": "shipped" },
    "statusCode": 200,
    "body": { "id": "{{params.id}}", "status": "{{state.checkout}}" }
  }
]
```

Calling ship while checkout is `pending` returns `409 Conflict`; paying first changes only `checkout` to `paid`, carries `orderId`, and leaves authentication intact.

See [Journeys](/docs/concepts/journeys) for the model and [Creating a Journey](/docs/guides/creating-journeys) for the authoring loop.
