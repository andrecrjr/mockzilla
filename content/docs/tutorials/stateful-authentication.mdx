# Tutorial: Authentication in a Customer Journey

> **Planned product:** This tutorial describes the Journey model being delivered. Existing workflows remain the current runtime until the replacement is complete.

Authentication belongs beside the rest of the customer story:

```text
auth:     signed_out → authenticated
checkout: browsing → pending → paid
```

Declare the `auth` Lifecycle and make its Actions explicit:

```json
[
  {
    "name": "Sign in",
    "method": "POST",
    "path": "/auth/sign-in",
    "requires": { "auth": "signed_out" },
    "transitions": { "auth": "authenticated" },
    "setFields": { "accessToken": "{{faker.string.uuid}}" },
    "statusCode": 200,
    "body": { "token": "{{fields.accessToken}}", "auth": "{{state.auth}}" }
  },
  {
    "name": "Get profile",
    "method": "GET",
    "path": "/me",
    "requires": { "auth": "authenticated" },
    "statusCode": 200,
    "body": { "id": "demo-user", "auth": "{{state.auth}}" }
  }
]
```

Checkout Actions can then require `auth: authenticated` without mixing authentication data into a cart or session resource. The `accessToken` field can be returned by later Actions, then clears on reset. A signed-out request to `GET /me` returns `409 Conflict` and names the unmet `auth` requirement.

Read [Journeys](/docs/concepts/journeys) for the full contract and [Creating a Journey](/docs/guides/creating-journeys) for the complete customer story.
